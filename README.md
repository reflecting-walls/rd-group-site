# RD Group, Inc. website

A static, pre-rendered site with a browser-based admin and **no backend**. All content lives in JSON files in this repository.

- **Public site:** plain HTML generated by `scripts/build.mjs` from `data/*.json` and `card/card.json`. Every project, service and town gets its own fast, crawlable page, plus `sitemap.xml`, `robots.txt` (AI crawlers allowed) and `llms.txt`.
- **Admin (`/admin/`):** manage projects and photos, the media library, review platforms and reviews, business info and the digital business card (`/admin/card.html`). Edits save as a draft in that browser. **Publish changes → Download update** produces a .zip with the changed JSON files and new photos at their paths in this repo.
- **Publishing:** upload the zip's contents to the GitHub repo (Add file → Upload files → Commit). Cloudflare Pages rebuilds the site in about a minute.
- **Estimate form:** posts to a free form service (Formspree or Web3Forms) that emails Rafal. Paste the form link under Admin → Business info.
- **Reviews:** type each platform's rating and count and paste reviews with links to the originals. Optional: set `GOOGLE_PLACES_API_KEY` and/or `YELP_API_KEY` as environment variables on the host, and add the Google Place ID / Yelp business ID in Admin → Reviews. Ratings and the newest reviews then refresh on every rebuild (Google shares up to 5 reviews, Yelp 3 excerpts).

The admin has no login, because there's no server to check one. It's hidden from search engines, and it can't change the live site by itself: only someone who can commit to the GitHub repo can publish.

## Folders

| Path | What it is |
|---|---|
| `scripts/build.mjs` | Site generator (Node 18+, no dependencies) |
| `data/` | Site content: business info, services, towns (with tiers), FAQs, projects, media, review platforms, reviews |
| `card/` | Rafal's digital business card (`card.json` is its content) with vCard download |
| `admin/` | Admin app (`index.html`, `admin.js`) and the card editor (`card.html`) |
| `assets/css/tokens.css` | Brand colors and fonts shared by the site, admin and card |
| `assets/css/site.css`, `assets/js/site.js` | Public site styles and behavior |
| `assets/js/data.js`, `assets/js/zip.js` | Admin data layer (`window.store`): loads the JSON, keeps the draft, builds the update zip |
| `assets/logo/` | New logo: mark, horizontal, stacked, reversed and favicon, all outlined SVG |
| `assets/uploads/` | Photos uploaded through the admin (arrive with each update zip) |
| `assets/img/materials/` | Stone/tile/wood swatches used as placeholders until real photos are uploaded |
| `_archive/` | The first version of the site, and the unused Supabase option |

## Run it locally

```bash
SAMPLES=1 node scripts/build.mjs   # include the sample projects/reviews
npx serve dist                      # open http://localhost:3000 and /admin/
```

## Deploy to Cloudflare Pages

1. In the Cloudflare dashboard go to **Workers & Pages → Create → Pages → Connect to Git** and pick `reflecting-walls/rd-group-site`.
2. Use these build settings:

   | Setting | Value |
   |---|---|
   | Production branch | `main` |
   | Framework preset | None |
   | Build command | `npm run build` |
   | Build output directory | `dist` |
   | Root directory | *(leave empty)* |

3. Under **Settings → Environment variables** (Production) add:

   | Variable | Value | Why |
   |---|---|---|
   | `NODE_VERSION` | `24` | Any Node 18+ works; `.nvmrc` also says 24 |
   | `GOOGLE_PLACES_API_KEY` | *(optional)* | Refreshes the Google rating and newest reviews on each build |
   | `YELP_API_KEY` | *(optional)* | Same for Yelp |

4. Deploy. Then under **Custom domains** add `www.rdgroup.info` and `rdgroup.info`. The domain's DNS is on Cloudflare, so this is one click each.
5. Redirect the bare domain to `www` so there is one canonical host: **Rules → Redirect Rules → "Redirect from root to WWW"** template (301).

### If you created a Worker instead of a Pages project

Cloudflare's newer "Workers & Pages → Create" flow may set the repo up as a **Worker** (builds show as "Workers Builds"). That works too: `wrangler.jsonc` tells it to serve `dist/` as static assets. Use build command `npm run build`, deploy command `npx wrangler deploy`, and the same `NODE_VERSION=24` variable. Custom domains are added under the Worker's **Settings → Domains & Routes**.

`_headers` (security, caching, and noindex for `/admin/` and `/data/`) and `_redirects` are copied into `dist/` by the build.

### After launch

- Create a free Formspree form that sends to Rafal's new email, and paste its link in Admin → Business info. Then download and upload that update.
- **Google Search Console:** add the `https://www.rdgroup.info` property and submit `https://www.rdgroup.info/sitemap.xml`.
- **Bing Webmaster Tools:** import from Search Console (Bing powers ChatGPT search and Copilot).
- **Google Business Profile:** make sure the name, phone and hours match `data/business.json` exactly and set the website to `https://www.rdgroup.info/`.
- Validate structured data with the [Rich Results Test](https://search.google.com/test/rich-results).

Sample projects and reviews are hidden in production builds. They only appear with `SAMPLES=1`.
